# Решения по архитектуре (ADR)

## ADR-001: модель LLM и бюджет (issue #12)

**Дата:** 2026-11-10
**Статус:** принято

### Решение

Единая точка вызова модели — `get_llm(role)` из `agent/llm.py`. Все агенты
получают модель только через неё; прямых вызовов API в коде агентов нет.

| Параметр | Значение по умолчанию | Переопределение |
|---|---|---|
| Модель | `gpt-4o-mini` | `LLM_MODEL` в `.env` |
| API | OpenAI-совместимый `/chat/completions` | `LLM_BASE_URL` (OpenAI, OpenRouter, локальный сервер) |
| Бюджет на прогон | `$1.00` | `LLM_BUDGET_USD` |
| Ключ | только `.env` (`LLM_API_KEY`) | — |

### Обоснование

- **gpt-4o-mini** — дешёвая модель с достаточным качеством для учебного
  контура: при цене `$0.15 / $0.60` за 1M токенов (input/output) полный
  прогон 25 кейсов оценочного набора укладывается в центы. Цены указаны по
  прайсу OpenAI на дату решения; перед реальными замерами их нужно сверить —
  таблица цен живёт в `agent/llm.py` (`PRICING_PER_1M`).
- **OpenAI-совместимый интерфейс** вместо привязки к одному провайдеру:
  замена модели — это строка в `.env`, а не правка кода агентов.
- **Бюджет** защищает от случайного слива средств: при превышении
  `LLM_BUDGET_USD` обёртка бросает `BudgetExceeded`, агенты обязаны
  деградировать gracefully, а не падать.

### Учёт токенов и стоимости

Каждый вызов возвращает в `wrapper.usage` запись `UsageRecord`
(agent, model, input_tokens, output_tokens, cost_usd) — из их суммы по
инциденту считается метрика **Cost per diagnosis** в eval-харнессе
(`eval/metrics.py`). Если провайдер не вернул `usage`, токены оцениваются
по ~4 символа на токен (помечено в коде как оценка).

### Последствия

- Тесты и локальные прогоны работают без сети и ключей: транспорт вынесен
  в параметр `LLMWrapper(transport=...)`.
- Смена модели команды = правка `LLM_MODEL` + при необходимости строки
  в `PRICING_PER_1M`.
