# Issue: единый запуск проверки кейсов

В `main` уже находятся 25 JSON-кейсов. Для запуска оценщика достаточно установить зависимости проекта:

```bash
python3 -m pip install -r requirements.txt
python -m eval.run
```

Результат: `eval/reports/latest.json` (папка добавлена в `.gitignore`). Команда печатает количество кейсов, F1, стоимость и Faithfulness.

**Важно:** в предоставленной версии `main` все агенты — заглушки. По умолчанию запускается именно этот граф, который обычно отвечает `unknown`. Отчёт содержит `mode: "stub_graph"` и предупреждение: это проверка работоспособности, а **не реальные показатели ИИ**. Стоимость такого запуска — $0, так как заглушка не вызывает LLM. При отсутствии `claims` Faithfulness = `null` (нет данных для оценки).

## Реальный запуск, когда агенты подключены

Создайте функцию с сигнатурой `run_incident(incident: schemas.Incident)`, которая запускает настоящий граф и возвращает `Diagnosis` либо словарь вида:

```python
{
    "diagnosis": diagnosis,  # schemas.Diagnosis
    "knowledge": knowledge_finding,  # optional schemas.KnowledgeFinding
    "telemetry": telemetry_finding,  # optional schemas.TelemetryFinding
}
```

Запуск:

```bash
python -m eval.run --runner package.module:run_incident
```

Раннер получает `Incident.metadata["source_dataset"]` и `["source_file"]`, чтобы найти телеметрию SKAB в отдельном хранилище. **Правильный ответ (`ground_truth`), список `evidence_docs` и имена разметчиков ему не передаются.** Перед реальным запуском нужно убедиться, что Telemetry Analyst умеет загрузить файл из настроенного `DATA_DIR` по этому относительному пути и что Knowledge Agent получает корпус из ветки Егора.

Для оценки заранее сохранённых результатов можно использовать:

```bash
python -m eval.run --predictions predictions.json
```

`predictions.json`: объект с ключами `case_id` и значениями `Diagnosis` (или объектами с полями `diagnosis`, `knowledge`, `telemetry`).

## Что означают метрики

- `root_cause.f1_macro`: средний F1 по классам, представленным в эталонах **или предсказаниях**. `f1_macro_all_classes` включает **все шесть классов**, даже если данных по пяти нет. Сейчас в эталонах только `equipment_fault`, поэтому сравнение шести классов ограниченно содержательно.
- `cost_per_diagnosis.mean_usd_per_diagnosis`: средняя стоимость по кейсам, для которых есть `Diagnosis.usage`. Если реальный агент не вернул `UsageRecord`, стоимость считается **неизвестной (`null`)**, а не нулевой.
- `faithfulness.score`: первая версия, **приближённая проверка**. Проверяются ссылки `Claim.citation_ids` и `Claim.evidence_refs` на `KnowledgeFinding`/`TelemetryFinding`, а при отсутствии findings — явно указанные результаты `Verification`. Это проверка наличия доказательной опоры, **не проверка смысла цитаты или истинности утверждения**. Если нет `claims`, показатель = `null`.

При ошибках отдельных кейсов они отмечаются в `cases[*].status`, а не незаметно исключаются из отчёта. Ошибка или отсутствие диагноза приводит к ненулевому коду выхода команды. Метрики считаются только по успешно полученным диагнозам; число таких случаев видно в отчёте.

## Что не включено

Код RAG-индекса и документы Егора находятся в других ветках (`codex/rag-index`, `feat/rag-corpus`). Данный PR **не объединяет их** и не изменяет чужие файлы. Реальный прогон станет возможен после интеграции соответствующих агентов и доступа к телеметрии.
